## Recommendation and user journey

Make Atlas an authored spatial entrance to real OpenRig work: bind selected existing objects to resources, inspect their current state, follow their context, and perform supported operations. Keep OpenRig as the coordination/lifecycle authority and Codex or Claude Code as the working environment. Atlas should remain useful while agents work, grow teams and change sessions entirely outside it.

A person opens their own map, selects a colleague's token, reads its purpose and follows **Open home note** to responsibilities, decisions and repository instructions. **Open agent** resolves the seat's current occupant. They send a question or create owned work with selected note references. The colleague uses native tools and temporary subagents, then grows or adopts another persistent seat when useful. Atlas discovers the changed roster; the person chooses whether and where to represent it. A task card leads to OpenRig's actual handoff and resulting artifact. The same seat can appear in another scene without becoming another agent. Closing Atlas interrupts none of this work.

This builds on [accepted spatial authorship and note-backed entrances](../../vault-and-roles.md#accepted-direction). Names, artwork and positions remain the author's choices. A collection is an Atlas organizational container, not automatically a rig or project. A project may link several scenes, rigs and repositories without requiring a universal directory layout.

No new agent primitive is needed. A deterministic adapter can resolve identities, reconcile state and dispatch supported commands. Existing seats provide judgment. An optional caretaker can maintain references through explicitly delegated OpenRig work; neither a standing governor nor an LLM intermediary is required for every click. This follows the inspected agentic-knowledge principles `earn-complexity` and `decide-with-ai-run-with-code`.

## Minimal architecture

Use three small components inside the existing plugin: **resource bindings**, a **shared OpenRig client/store**, and **selection-driven inspectors/actions**. Keep renderers and native map persistence responsible for ordinary Atlas behavior.

**Identity.** Propose a versioned external reference separate from immutable `recordingReference`: connector/instance key, resource kind and opaque resource ID, with rig/node coordinates where required. Instance configuration maps that key to a host/daemon endpoint. Names and session addresses are lookup hints, not primary identity. Distinguish image asset, scene object, resource, role/home note, seat, occupant generation, native conversation, queue item, artifact revision and project. Multiple objects share a resource key; copying one creates only a new local object. Removing and recreating a same-named seat must not silently rebind old objects. Keep role-to-seat assignment explicit and allow vacant roles.

**Transport.** Prefer documented/inspected daemon HTTP routes for reads and supported mutations, with a desktop CLI adapter for operations whose behavior includes local terminal opening. Atlas already uses Obsidian `requestUrl`; streaming needs a separately verified desktop transport. Start with bounded polling, then add SSE without a companion daemon. Never read/write OpenRig's database directly. Keep endpoints/credentials in local connection settings, outside exported maps.

Installed MCP exposes 18 tools, without the full queue/context/lifecycle surface. It is an optional transport, not the capability ceiling. `/healthz` supplies build identity; `/api/info` supplies an installation locator, not a capability schema. Maintain a small, tested per-operation compatibility table using build/version plus non-mutating response validation. Distinguish supported, unavailable and unverified operations. Preserve unknown fields/kinds opaquely, offer source/native navigation, and extend the adapter deliberately. Do not infer executable controls from arbitrary metadata or promise complete machine-readable discovery.

**State.** Fetch rig/node inventory and scoped queue detail into one shared store, deduplicated across views. Events invalidate relevant reads rather than rewriting map objects. Installed `/api/events` supports sequence replay via `Last-Event-ID`, but rig filtering excludes queue events without `rigId`. Installed `/api/queue/sse` has neither replay nor `queue.updated` in its event filter. Use scoped snapshot polling as the baseline; a global event subscription may invalidate only connected resources where appropriate. Re-fetch on connection, focus, command completion, cursor reset or uncertain coverage. Preserve a timestamped stale view offline, disable commands requiring fresh resolution, and never queue hidden mutations for reconnect. A failed or incomplete listing cannot establish resource deletion.

**Commands.** Re-resolve target identity immediately before dispatch. Record a lightweight local receipt with target, actor, operation, parameters/reference digest, time and authoritative result IDs. This is diagnostic evidence, not another task ledger. A successful HTTP response is insufficient: transport can retain delivery, and terminal results can report absent/degraded seats. Separate submission, delivery, claim, completion and acceptance. Use supported operation/delivery IDs where available; after an ambiguous timeout, inspect authoritative state before retrying. Board undo remains purely local.

**Native entrance.** Source supports rig/pod/saved terminal views; no direct seat-view argument was found. `rig seat switch-client` targets an already attached client. Desktop window opening additionally lives in CLI `openTerminalWindow`, so HTTP `/terminal/open` alone must not be advertised as opening a visible desktop. Initially label the verified fallback **Open team terminal**. Qualify a seat-specific composition or obtain a narrow upstream seat-open primitive before labeling it **Open agent**. Remote HTTP-only hosts degrade honestly to native connection guidance.

## Decisions, gaps and limits

- **Choose a narrow binding contract now.** Recommend direct external reference plus optional home-note link. Add a separate role identity only where a role genuinely outlives its assigned seat. Defer universal project manifests and ontology editors.
- **Choose the first operating controls.** Recommend native opening, messaging, owned-work creation and artifact navigation before lifecycle forms. This is sequencing, not a permanent read-only ceiling.
- **Choose honest human attribution.** Atlas must not impersonate the selected agent when sending or changing work. Use an explicit supported human/source identity; surface claimed-versus-transport provenance. Qualify each mutation's actor requirements against the installed route.
- **Upstream gaps or limitations:** no general capability manifest established; current event filtering cannot be treated as a complete rig-scoped queue feed; direct seat desktop opening is not established; plugin CLI is inspection-only; remote HTTP terminal composition degrades. These deserve narrow contracts or native fallbacks, not a new execution engine.
- **Local integration gaps:** generic home links, live transport/store, identity resolution, action receipts, reconciliation, host rebinding and inspector controls. Historical `recordingReference` should remain historical rather than silently becoming a live locator.
- **Chosen scope:** no automatic layout, mandatory workflow, automatic seat creation for helpers, standing caretaker or transcript ingestion. Future capabilities remain possible through native operation and adapter extension.

Remaining uncertainties include Obsidian streaming/origin behavior against the configured daemon, event retention/reset guarantees, operation-specific retry guarantees, visible terminal behavior, and cross-host artifact accessibility. None was exercised here. Current official context/edge documentation names a 0.6.6 baseline; installed 0.6.10 source/help governs this proposal. The [context guide](https://openrig.dev/docs/context) supports addressed retrieval and plugin inspection; the [edge reference](https://openrig.dev/specs/edge-types) distinguishes launch/escalation behavior from descriptive relationships. The [world-building article](https://openrig.dev/blog/how-my-agent-teams-find-their-way) supports navigable reading routes and explicit authority distinctions, not a verified Atlas capability. The [feature map](https://openrig.dev/features) is useful discovery guidance, not runtime proof.
