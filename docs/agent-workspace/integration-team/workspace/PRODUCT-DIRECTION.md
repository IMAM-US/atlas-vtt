# Integration workspace product direction

Accepted owner direction, 2026-10-18 UTC. Atlas is an editable spatial dashboard for this project. Agents retain their repository-native Codex or Claude Code harnesses. OpenRig supplies persistent seats and existing communication, coordination and lifecycle. Repository/workspace files own instructions, knowledge, artifacts and decisions. Atlas does not add a second governance system.

An agent token represents an actual stable seat; its Atlas object identity remains separate. Its compact card leads with purpose, native harness/model, repository and actual cwd. Native IDs, recorded work and provenance remain secondary. The intended primary action is Open agent, resolving current native context through supported mechanisms. The current milestone has metadata and opening instructions only: no native launcher, live status source or verified per-seat URI. A stopped seat must not be silently restarted or replaced.

The illustrated cartography/Atlas bench, systems/OpenRig bench, shared review table and evidence library are authored spatial context. Notes and labels define their editable meaning. Placement does not dispatch work, establish acceptance or grant access. Current explicit scene snapshots are bounded reading assignments, not automatic subscriptions.

Develop through real scenarios, then the smallest demonstrated missing Atlas capability. Agent creation/import, direct native-agent navigation and live context feeds remain separate follow-ups. No permission interface, general live connector or automatic dispatch is authorized.

Accepted owner clarification, 2026-10-18: each Atlas project can explore its own roster, repository harnesses, context, configuration and spatial expression. A new Codex session may help configure a project; project, scene, seat and conversation identities remain distinct. This integration studio is one concrete configuration, not a universal project template. Explicit reuse across projects should preserve provenance and distinguish a shared reference from a copied representation, artifact or configuration. Versioned files and small experiments are the intended development approach; a project manifest, composition/import mechanism and compatibility rules remain proposals. No such framework or live integration is added in this milestone.
