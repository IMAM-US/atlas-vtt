# Astra Representation: Forkwater

An independently authored Atlas project showing **one evolving world through several explicit accounts**. Similar pictures can represent different native participants; different appearances can represent the same participant. Places organize meaning without becoming a compulsory execution topology.

Import [Astra Representation v1.atlas-collection.zip](<Astra Representation v1.atlas-collection.zip>) as its own collection. Open **Astra - 01 Forkwater** and fit the whole map to the view. The upper-left pin opens the short start note. The coordinator owns import into the isolated review vault and visible verification.

Inspect three things:

1. **Archive versus camp:** the original investigator and the current native fork share a name and portrait but have different node/conversation identities. Both reports remain readable through real note pins.
2. **The undertaking and result quay:** actual queue records are distinguished from authored interpretation and owner acceptance. The work note gives the existing native terminal/context route; the map does not pretend to launch or message an agent.
3. **Council perspective:** the scene-link pin opens **Astra - 02 Council**, where author and context-keeper appearances point to the same current native node and note. Move or rename an appearance without confusing that board edit with a native lifecycle action.

The river world and owl portrait were generated with the callable built-in `image_gen__imagegen` tool. All meaningful labels, pieces, lines and links remain native editable objects. The two scenes contain **4 token appearances, 32 text objects and 16 pins**. Geography and role captions are authored interpretations; native observations are dated **2026-10-19 03:01:49 UTC**.

- [Unpacked manifest](unpacked/manifest.json) and `unpacked/files/` contain the complete editable bundle content.
- [Representation ledger](sources/representation-ledger.json) makes the semantic bindings explicit as an authoring sidecar, not a new plugin schema.
- [Native evidence](sources/native-evidence.json), unchanged own report sources, and editable map/token art specifications are under `sources/`.
- [Artwork prompts](artwork/prompts.json) and [provenance](artwork/provenance.json) retain generation method, original files, dimensions, hashes and visual findings.
- [Validation](validation.json) records the actual Atlas manifest check, file hashes, local references and conservative bounds checks. [Deliverable digests](deliverables.json) identify final bytes.

**Verification boundary:** Atlas's actual format-4 manifest validator accepted the bundle manifest; all 17 payload hashes and 37 note/scene references passed checks. The generated images were visually inspected. The project has not been imported or rendered in native Atlas by this author; exact text layout, pin behavior, save/reopen and small-screen token readability await the coordinator. The separate forge schema compiler could not run because the existing offline environment lacks `jsonschema`; no dependency was installed.

Only this project directory was authored. No peer proposal, peer project or coordinator synthesis was read; no plugin source, shared vault, runtime configuration or third project was changed.
